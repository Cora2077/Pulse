# Pulse 日常交易纪律设计

2026-10-01 · 详细实施计划。仓位分账、多逻辑卡片与交易前检查尚未实施。

依据《厘清交易逻辑》中目前可读取的讨论：明确提出了低仓位焦虑和怕踏空；此前方案还讨论了战略底仓、机动仓、观察底仓，以及一家公司承载多条投资逻辑。完整原始问题清单未全部返回，因此下面区分已确认的问题和需要防范的行为，不把推断当成你的历史事实。

目标：让 Pulse 在每一次交易前呈现你事先写下的条件，并在成交后检查执行偏差。系统帮助执行你自己的规则，不把提醒、技术指标或 AI 判断当作买卖授权。

## 问题与系统功能的对应

| 问题 / 需要防范的行为 | 设计 | 系统呈现的反馈 |
| --- | --- | --- |
| 已明确：低仓位时担心股票连续上涨、再也买不到 | 把战略底仓、观察底仓、机动仓和预留现金分开 | 显示“战略参与情况”和“机动资金是否有符合规则的用途”，避免只盯总仓位 |
| 需要防范：看到上涨后临时改变买回计划 | 冲动交易冷静期，保存交易前的三问答案 | 冷静期间保留原计划，倒计时结束后重新核对现价、条件和风险 |
| 需要防范：做 T 或减仓时不清楚动的是哪部分仓位 | 持仓分账，每条计划明确仓位用途 | 卖出计划显示剩余底仓及与目标底仓的差距 |
| 需要防范：投资逻辑、技术条件和短期消息混在一起 | 多条投资逻辑卡片，分别保存证据、证伪条件和下次检查时间 | 单条逻辑变化只提醒检查与它关联的计划，避免自动影响整家公司 |
| 需要防范：盘中临时修改理由、价格或数量 | 计划检查单与修改记录 | 显示修改前后差异、风险金额变化，以及新的理由 |
| 需要防范：个股和 ETF 标签不同，实际暴露仍集中 | 板块分类、上限及计划执行后的预览 | 显示同币种板块占比；ETF 第一版按人工分类整体计入 |
| 需要防范：复盘只看赚钱与否，遗漏规则执行情况 | 行为标签与按计划执行统计 | 分开呈现收益结果、执行情况和样本数，不用一次盈利证明临时变更正确 |

## 1. 仓位分账：明确每一份持仓的用途

### 入口和页面

新增独立的“仓位池”页面，默认按用途分四列：未分配、战略底仓、观察仓、机动仓。现有持仓总览保留行情与账本；增加简短用途摘要和进入仓位池的入口，不继续加宽表格。标的详情中显示该标的的同一份分账，编辑后所有入口同步更新。

提供两种查看方式，使用同一份数据：

- **全局仓位池**：四列摆放卡片，用于归类和内部转移。列头显示卡片数、同币种参考市值与用途标签。
- **按标的分账**：一个标的一行，横向呈现其战略、观察、机动和未分配份额；便于检查“这个标的还有多少底仓”。窄窗口改为按标的纵向分组。

颜色表示用途，所有池子都有文字标签；红绿涨跌色不承担用途含义。池子市值按币种分别统计，缺报价单独提示；不把不同标的的股数相加，也不把不含现金的参考市值称为账户仓位。行情来源与时间放在页面统一位置，只对个别旧报价或缺报价显示卡片提示，避免重复冗余。

### 卡片代表什么

一张卡片表示“某个买入来源目前仍持有、且具有一个用途的一份数量”。一次买入可以拆成多张卡片；卡片不是完整历史成交，也不是尚未执行的计划。

用买入 1000 股、之后已卖出 200 股作演示：当前剩余 800 股，可以分成战略 400、机动 200、未分配 200。三张卡片都保留同一个买入来源；拆分或拖拽后总数仍是 800。这个示例只说明数量守恒，不预设个人比例，也不声称旧历史能够自动推导这样的来源。

卡片默认显示标的名称、剩余数量、买入日期、来源成交价、关联逻辑或策略。数量是最醒目的信息；未关联显示“待补逻辑”。点击展开后才显示原成交数量、已明确归属的卖出、转移记录、复查日期和关联计划。来源成交价明确标注，不冒充现有账本的加权平均成本。

已卖出的份额进入单独历史记录，不继续占据当前池子。未执行计划在侧边详情中显示执行后的预览，不作为真实持仓卡片拖拽，也不计入池子数量或市值。

### 拖拽与卡片操作

| 操作 | 页面反馈与数据变化 |
| --- | --- |
| 整张拖入其他池子 | 拖动时显示卡片影子和目标池高亮；显示将转移的标的、数量；放下后更新两池统计 |
| 放回原池或拖到无效位置 | 不产生修改记录，不改变数量 |
| 从战略底仓移出 | 在同一转移面板填写原因；显示本标的底仓前后数量、保留量差距，确认后才转移 |
| 部分转移 | 点“拆分 / 转移”，填写数量和目标池；原卡保留余量，新卡继承同一买入来源 |
| 转移全部数量 | 移动原卡，保留卡片身份；不留下零数量卡片 |
| 手滑后撤销 | 页面提供最近一次分账操作的撤销；拆分时同时恢复两部分，保留原成交 |
| 逻辑需复查 | 卡片出现文字标记；只提示引用这条逻辑的份额，不自动转池或卖出 |

普通整张转移直接生效，页面提供撤销，避免每次都确认。战略退出需要原因，是为了记录用途变化；用户设定的底仓保留量在此显示差额，不作为不能保存真实成交的门禁。转入战略仓但缺逻辑时显示待补，不自动生成投资理由。

每张卡都提供“转移 / 拆分”按钮，完成与拖拽相同的操作，支持键盘及无法拖动的设备。数量使用现有标的数量精度校验；演示中的股票整股不扩展为所有市场必须整数。数量必须有限、为正且不超过当前卡片；原池与目标池不同。转移完成后播报简短结果，键盘焦点留在可继续操作的位置；取消不写入。

初版不做拖卡即下单、不做拖入现金池视为卖出，也不批量合并不同买入来源。等实际卡片数多到影响使用，再增加筛选和多选操作。

### 游戏式拖拽手感

借鉴装备栏移动物品的反馈，让每个动作都有清楚的结果：

| 阶段 | 视觉与交互 |
| --- | --- |
| 拿起 | 移动超过短距离后拿起；卡片浮起并轻微倾斜，原位保留轮廓，避免列表突然塌陷 |
| 跟手 | 卡片跟随指针，带着标的、数量与目的地；轻微倾斜随水平移动变化 |
| 经过目标池 | 可接收池显示轮廓；当前目标展开接收槽，显示这只标的转入后的数量；其他标的的行不可接收 |
| 放下 | 普通转移用约 220 毫秒吸附到接收槽，落位后短促回弹、更新数量并提供撤销 |
| 拆出部分 | 桌面端按住 Shift 拖动，接收槽切换为拆分提示；松手打开同一个数量面板，由用户填写数量，确认前不扣份额 |
| 移出底仓 | 接收槽提示需填写原因；松手后进入已有转移面板，确认后才改变分配 |
| 取消 | 放回原池、无效位置、按 Esc 或中断手势均不改数量；正常松手时卡片回到原位 |

不使用积分、中奖式动画或声音奖励。减少动态效果开启时关闭倾斜、飞入与回弹，保留接收槽和数量预览。触屏只从抓手发起拖动，卡片其余区域保留正常页面滚动；键盘继续使用同一个转移面板。拖拽动画结束前锁定本次手势，外部状态更新会取消悬浮卡片，避免拖拽旧份额覆盖新分配。

### 第一次使用

1. 原持仓全部显示为“未分配”。现有账本按移动加权平均计算，没有保存旧卖出消耗了哪笔买入，因此每个标的建立一张“现有持仓待归类”卡，不伪造逐笔剩余数量或先进先出规则。
2. 用户通过拖拽或拆分完成分配；也可在标的详情填写各用途数量。未分配为剩余数量，不能为负。已有持仓卡的来源明确显示为当前账本快照，不伪装成某笔历史买入。
3. 可分别填写目标底仓和需要保留的底仓数量。目标表示期望，当前数量来自真实账本，二者不混用。
4. 战略与观察部分可以连接逻辑卡片；尚未连接显示“待补逻辑”，不改写实际持仓。

初版支持现有净长仓。净空头和多空反转后的空头显示“此状态暂不适用分账”，保留原始成交及历史分账记录，不套用长仓的保护规则。

### 买卖与内部转移

| 用户操作 | 分账如何响应 |
| --- | --- |
| 新建买入计划 | 选择买入后进入哪个用途；只预览，不增加持仓 |
| 新建卖出计划 | 选择具体卡片及数量，可分摊到同标的多张卡；显示该用途剩余数量和底仓差距，保存计划不扣持仓 |
| 录入实际成交 | 买入可关联原计划并建立来源卡；卖出可关联原计划，明确从哪些卡扣减；只处理实际成交数量 |
| 一份计划分两次成交 | 每笔分别关联同一计划，累计数量并列出剩余计划数量 |
| 将观察仓转为底仓 | 更新所选卡片用途或拆出部分；保存数量、日期和原因；不产生买卖成交、费用或盈亏 |
| 补录无关联交易 | 允许保存事实，分账标记“待核对”，不猜测属于哪个用途 |
| 修改、删除历史成交或直接校准持仓 | 重新计算真实数量，保留旧分配供核对，标记受影响标的 |

卖出计划若超过所选用途数量，不能标记为“已完成检查”。用户可以调整数量，或明确选用其他用途。动到底仓保留量时，在同一页解释“执行后剩余多少、低于自己设定的保留量多少”，允许填写原因继续，不弹出重复确认框。已经发生的真实成交始终允许录入。

### 实现边界

现有 PositionLedger 继续是实际数量、成本、费用和盈亏的唯一来源。分账增加轻量的持有份额记录：稳定身份、来源成交或旧持仓快照、当前数量、用途、逻辑/策略关联，以及明确的卖出归属与转移记录。卖出归属仅描述用户选择的用途扣减，不改变账本的移动加权平均核算。第一版不增加税务批次、不推算历史每一天的桶内收益，也不展示无法可靠核算的卡片已实现盈亏。

每次分账修改都校验同标的数量与真实账本一致；拆分还校验同一来源的总量守恒。账本有修改、删除、补录或直接校准时，核对来源与总量：出现差异就保留旧分配并标记待核对，明确显示差额，不自动从其他用途扣数量来凑平，也不把未核对池子统计显示为完整结果。数量恰好相同也不能忽略失效来源。

撤销仅撤销最近一次尚未被后续成交、同步或其他编辑改变的分账操作；原成交不会被撤销。若底层数据已变化，重新核对后操作，避免旧撤销覆盖新的持仓。历史转移和卖出归属仍可追溯。

没有券商可卖数量和现金数据时，不把“机动仓 300 股”称为“可卖 300 股”，也不展示虚假的账户仓位或可用资金。账户快照与只读网关放在后续阶段。

**验收：** 拖拽、按钮和部分转移结果一致；同池放回和取消不写入；拆分及撤销总量守恒；战略移出保留原因；计划不改变持仓；分批成交不重复计数；修改旧成交后能发现总量及来源差异；内部转移不产生盈亏；旧持仓不伪造逐笔来源；空头状态不会出现错误底仓提示。

## 2. 多逻辑卡片：让不同理由各自有依据和复查时间

### 入口和一张卡片的内容

把现有“买入理由”页升级为“投资逻辑”。上方是卡片列表，选中后编辑；默认收起证据明细，保持详情页简洁。

| 字段 | 用户填写的内容 |
| --- | --- |
| 名称 | 一句能辨认的名称，例如“某产品放量” |
| 核心判断 | 原因 → 中间变化 → 对公司的影响，用自己的话填写 |
| 支持证据 | 摘要、原始链接、资料日期、添加时间，可多条 |
| 证伪条件 | 发生什么会否定或削弱这条逻辑 |
| 状态 | 待验证 / 观察中 / 需复查 / 已否定 / 已归档 |
| 复查时间 | 最近复查日期和下次复查日期 |
| 关联 | 哪些持仓卡片、哪些计划正在使用这条逻辑 |

最少填写名称和核心判断就可保存草稿；证伪条件和复查时间未补齐时显示缺项。初版不会把自然语言证伪条件变成自动买卖规则。

### 一家公司承载多个理由

例如同一家公司保存“产品放量”“行业供需改善”“短期事件观察”三张卡片，各自有状态和证据。战略调整要选择主要依据，观察仓选择正在验证的依据，机动交易可以选择公司逻辑，也可以仅选择已有的技术策略与条件。

“一条逻辑需复查”只影响引用它的仓位与计划。其他独立逻辑保持原状态。系统列出受影响项目，由用户决定是否修改；不会自动清仓、取消计划或判断公司整体失效。

### 和事件日历连接

日历卡片增加“加入逻辑待核对事项”：选择目标逻辑，带入事件标题、日期、来源链接。预约财报日期只是复查安排，不能作为已经发布的财报证据。待用户阅读原文后，再填写结论与证据。

复查到期时进入工作台“今日需复查”。复查操作填写“维持 / 调整 / 否定”及简短理由，设置下一次日期。修改保留旧内容与修改时间；不在每次行情刷新时生成历史版本。

### 老数据迁移与留存

原买入理由原样保存为第一张“原买入理由”卡片，证伪条件和复查日期留空，由用户补充。迁移只执行一次，卡片有稳定身份，重启和同步不重复生成。原字段保留以兼容旧接口；旧字段后续出现变更时提示核对，不悄悄覆盖结构化卡片。

从自选移出一个仅有逻辑卡片或计划的标的，也必须保留这些记录；目前保留规则不完整，需要随此阶段修正。归档逻辑不破坏历史计划的引用，重新加入标的可以找回资料。

**验收：** 旧文字不丢失；独立逻辑不互相连带否定；证据来源可打开；预约事件不会被当作已发布信息；复查提醒去重；归档或移出自选后历史引用仍可读。

## 3. 交易前检查：把用途、依据和风险装进同一份计划

### 一个统一入口

现有计划编辑页、工作台风险计算、图表计划入口都打开同一套计划表单。MCP 写入路径也走同一份数据校验；不能只给一个页面加检查，其他入口仍创建缺少假设的“已检查计划”。

流程为“保存草稿 → 补齐条件 → 手动核对 → 等待条件 → 成交后录入”。盘后可以写次日草稿、用参考价格估算风险；收盘或旧行情不会显示为盘中条件已满足。

### 表单只增加三组内容

1. **用途与依据**：战略调整 / 观察验证 / 机动交易；选择仓位用途；关联逻辑或策略；写下本次条件。
2. **价格与数量**：买卖方向、触发价、触发方向、数量。价格条件支持“达到或低于 / 达到或高于”，原计划沿用原来的比较方式，避免升级后改变含义。量能、形态、消息核实等初版由用户勾选，不声称系统已自动识别。
3. **风险与影响**：复用现有计算器填写防守价、目标价、预算、费用、滑点、数量步长和投入上限；同时显示计划执行后标的、板块和仓位用途的变化。

字段随用途调整：

| 计划类型 | 必要检查 | 不强加的条件 |
| --- | --- | --- |
| 战略买入或调整 | 关联逻辑、调整原因、数量、投入与集中度 | 不强制使用机动交易的固定止损或目标价 |
| 观察买入 | 正在验证的逻辑、观察上限、复查日期、数量 | 不自动升级为战略仓 |
| 机动买入 | 策略/入场条件、防守价、目标价、风险预算、费用与滑点假设、数量步长 | 不要求每笔技术交易都编一条基本面理由 |
| 卖出或风险退出 | 所选用途、实际数量参考、执行后底仓变化、原因 | 不强制填写买入盈亏比，也不妨碍录入已经发生的退出 |

费用和滑点可明确填写 0，也可保持“待填写”；未填不当作已核实的零成本。盈亏比、板块上限、底仓保留量等阈值由用户设定，不预设 3:1、固定比例或冷静期。

### 检查卡片显示什么

| 检查项 | 显示的结果 |
| --- | --- |
| 行情 | 价格、来源、时间、延迟声明；当前 / 参考 / 缺失 |
| 用途分配 | 计划前后该用途数量，分账是否待核对 |
| 逻辑与条件 | 依据是否已否定、到期未复查，人工条件还有哪些未核对 |
| 风险 | 估算投入、按假设价格的亏损、目标盈利、盈亏比，与自设预算的差额 |
| 集中度 | 同币种标的和板块占比变化；缺报价与现金缺项明确列出 |
| 近期事件 | 事件时间、来源、是否预约，用户是否已经了解 |
| 券商约束 | 未接入现金和可卖数量时显示无法核验，不能给出通过结论 |

状态分为“已填写”“待人工核对”“存在偏差”“数据不足”。价格到价通知只是提醒核对，不是检查通过，更不是成交。

结构无效的数据（负数量、失效数字、超过实际分配等）不能标记检查完成。与用户自设规则存在偏差时，可以改计划，或在页内填写例外理由继续；所有结果保留。草稿和真实成交记录不会被这些提示阻挡。

### 保存当时的决定，防止事后重新解释

风险计算保存计划时，同时保存入场、防守、目标、预算、费用、滑点、步长与投入上限。计划每次价格、数量、用途、条件或关联逻辑变更保存一个旧版本，新版本的检查状态变为待核对。行情每次更新只刷新展示，不自动保存版本。

手动完成检查时保存一份简短快照：当时计划版本、所引用逻辑的版本、报价与来源时间、风险结果、规则偏差及例外理由。逻辑后来变更，不覆盖这份快照；再次交易前提示依据已有更新。

仓位卡片拆分、转池或实际数量变化后，关联卖出计划保留原引用，并重新核对当前用途和数量；引用已失效或不足时显示待核对，不自动改卖另一张卡。历史检查快照保留原状，不因为当前分账变化而重写过去的决定。

风险估算不保证真实损失上限，止损价也不保证执行价。[Investor.gov 关于止损执行价格的说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-15)

### 把成交与计划接通

计划增加“记录已成交”入口，带入计划、版本和用途，用户填写真实价格、数量、日期和费用。已有交易可手动关联计划；不按日期或价格相近自动猜测。

一份计划可以关联多笔成交，累计数量计算来自真实成交：计划 200 股、先记 100、再记 100，只得到 200。超过原计划仍可保存真实成交，并显示数量偏差，不把原计划改成新的成交数。删除或修改成交后重新计算累计；已失效的关联显示待核对。

现有单个 filledTransactionID 保留读取兼容，编辑旧计划必须保留它。新增交易侧保存关联计划和版本，从交易查回计划，避免两边维护两套重复数量。

**验收：** 所有计划入口一致；保存后测算假设能找回；改数量或逻辑后检查失效；旧行情只能作参考；人工条件不会自动变成通过；部分成交累计正确；录入真实成交不被计划规则阻断。

## 4. 冲动交易冷静期：给临时变更留一个可检查的间隔

计划页和工作台提供“我现在怕踏空”按钮，由用户主动触发，不用算法诊断情绪。触发后保存当时价格、原计划及冷静期结束时间，并呈现三问：

- 如果我没有之前的买卖经历，今天还会主动选择这个位置吗？
- 失效点在哪里，当前估算风险与收益是否符合我设定的条件？
- 新的交易条件是什么，还是仅仅因为价格在上涨？

在 Pulse 内，冷静期暂停新增机动买入计划的一键保存。仍可编辑草稿、查看风险、查看退出方案，以及补录真实成交。用户可以提前结束冷静期，但需记录原因；系统不会让“强制等待”阻止事实账本的更新。

冷静期结束只是重新检查的入口，不代表条件合格。倒计时使用保存的截止时间，重启后继续；结束后刷新报价并重新计算风险。

Pulse 当前没有券商下单通道，因此这个流程只能约束 Pulse 内的计划操作，不能阻止用户在券商客户端下单。若外部已经成交，允许立即补录并标记绕过原因。未来如果明确授权交易网关，相关约束需在所有交易入口统一执行，不能只在界面按钮上检查。

## 5. 今日工作台：让“正在等待”有具体的内容

在本次工作台之上补充三个区域：

- **战略参与**：各标的底仓、目标差距、逻辑复查状态。避免把“机动仓暂时没有买点”直接解释为“完全没有参与”。
- **机动等待**：计划在等待什么、距价格条件多远、哪些人工条件尚未确认。没有条件成立时显示等待原因。
- **今日需要处理**：底仓/机动分配差异、未复查逻辑、超限板块、冷静期内修改、近期事件以及待补复盘。

首屏优先显示需要处理的项目。实时涨幅排行保留在现有自选列表，不让它占据纪律工作台的主位置。提醒按项目去重，不因为行情反复穿越就连续弹窗。

## 6. 复盘：同时记录结果和行为

沿用本次完整持仓轮次的策略统计，再增加用户可选行为标签，例如“计划内执行 / 追涨变更 / 过早退出 / 临时扩大数量 / 绕过冷静期 / 无法归类”。标签由用户填写，系统可以提示核对，不能凭盈亏猜测动机。

计划关联成交后，对照计划创建时的价格、数量、风险假设与实际成交。原计划保留历史版本，避免事后修改后看起来始终按计划执行。未记录的费用、没有完整开仓历史、无法可靠归属策略的轮次明确标记，不自动补造。

每周展示：明确复盘的计划执行率、各类偏差次数、相关已实现盈亏、样本数量。先回答“反复发生了什么”，再由用户判断该调整哪些规则。暂不做“若没卖出本可以赚多少”的主指标，以免持续强化后悔和追涨压力。

## 数据和实施顺序

复用现有 WatchItem、TradePlan、PositionTransaction、同步和备份，不新建服务端、订单系统或 AI 自动决策模块。

### 开发前确认的基础缺口

- 买入理由目前只有一段字符串，需迁移成有稳定身份的多张卡片。
- 风险计算目前保存普通计划，不保存测算假设，无法事后重现原决策。
- 交易复盘能读取 filledTransactionID，但普通操作尚未写入成交关联；编辑计划还会丢失旧关联。
- 移出自选时，仅有逻辑或计划的标的目前可能不被保留，需扩展留存条件。

以上是代码核对得到的实施事项，不表示这些新增模块已经完成。

### 第一阶段内部分四批交付

| 批次 | 做什么 | 用户可验收的结果 |
| --- | --- | --- |
| A：数据基础 | 新字段兼容、升级前备份、计划关联保留、风险假设保存、成交关联与留存修正 | 原数据无损；旧关联编辑后仍在；从计划补录两笔成交能累计 |
| B：仓位分账 | 仓位池页面、剩余份额卡片、拖拽/按钮转移、拆分/撤销、旧持仓归类、明确卖出归属、数量与来源核对 | 将同一标的拆入底仓和机动仓，撤销一次拆分，再录入部分卖出核对剩余数量 |
| C：多逻辑卡片 | 旧理由迁移、独立逻辑与证据、复查日期、关联仓位/计划、日历待核对事项 | 同一标的建立两条逻辑，调整一条时只有关联项目提示复查 |
| D：统一检查 | 统一计划表单、按用途显示字段、规则差额、检查快照、修改记录、工作台汇总 | 创建一份机动计划，检查、改数量、补录成交后能完整回看 |

每批都先完成核心校验与同步/备份恢复检查，再更新日常安装版、验证真实页面。一次验收一个完整操作链，不把大量未连通入口同时塞进界面。时间在实施时按实际范围评估，这份设计不把未核对的工时当作承诺。

### 后续阶段

第二阶段：冷静期 + 行为复盘。计划版本和检查快照已在第一阶段形成，第二阶段使用这些依据统计临时变更、例外和绕过原因。

第三阶段：带更新时间的人工账户快照；如账户网关存在且另行授权，再加入只读账户核对。没有完整资金与可卖数据时不推导这些数字。

### 保存、同步和冲突

- 真实成交继续只存于现有账本。用途分配、逻辑卡片、计划假设/历史/检查、成交用途与计划关联都是附加信息。
- 逻辑与证据按稳定身份合并，互不覆盖不同卡片。移除自选、归档逻辑及删除关联对象不连带删除历史成交和检查快照。
- 同一份分账的并发修改不能把几个数量分别相加。保留两份候选并要求核对，合并后再验证与真实数量是否一致。
- 新增结构必须通过本地读写、文件夹同步、完整备份恢复、便携归档和 MCP 读回。新结构使用新版本，旧文件可迁移；新格式的共享文件由旧客户端明确拒绝，避免丢字段写回。
- 本地升级前保留旧快照；含新结构的数据使用新的本地保存版本，防止回退到旧应用时覆盖新结构。恢复仍沿用现有预览、恢复前备份和原子替换。

### 验证清单

1. 老理由迁移一次，重启/同步不多生成卡片；留存和恢复可找回逻辑与计划。
2. 现有持仓不因分账改变，内部转移不产生盈亏；真实数量变动产生一致的差异提示。
3. 部分成交、超计划成交、改删成交及多空反转不篡改原计划或事实账本。
4. 计划修改和逻辑版本变化使检查待核对，历史快照仍可读。
5. 盘后草稿可保存；行情缺失、旧报价和人工条件未确认不会显示盘中已满足。
6. 并发改不同逻辑卡片都保留；并发改同一分账保留候选，不能制造重复持仓。
7. 临时数据测试通过后，在日常版核对正常/窄窗口布局、键盘操作和取消操作；界面测试不写入未经用户选择的真实交易。

## 验收条件

1. 分账不会改变实际成交；分类总量不一致时明确提示。
2. 一条投资逻辑变更不影响其他独立逻辑，关联计划可以追溯。
3. 历史、缺失或异常报价不能显示为有效的盘中触发条件。
4. 冷静期重启后仍有效，实际成交永远可以补录。
5. 计划修改可回看；统计不把分批平仓重复算作多个完整持仓轮次。
6. 现金缺失时不展示账户仓位，未填写的费用和复盘答案不当作零或否。
7. 新数据可以同步、备份和恢复；升级文件格式时旧客户端明确提示需要更新。

## 与本次五项功能的关系

本次已经开发的是风险计算、人工板块分类与上限提醒、今日工作台、完整持仓轮次的策略分析，以及有来源的事件日历。本文的分账、多逻辑、冷静期和行为偏差模块是后续设计，尚未安装，避免把设计草案误认为现有功能。
