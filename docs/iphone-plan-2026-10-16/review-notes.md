# v2独立评审与主代理审定

2026-10-16，按用户「不行的话找Kimi K3聊一下」的许可，使用本地脚本指定Kimi Coding / k3完成一次只读产品评审。只提供了不含真实账户数据的自包含产品问题，没有提供聊天记录、凭据或用户账本。没有让评审模型执行交易或改文件。

## 采纳

- 上版会话式手动启动违背日常使用习惯，应改为持久关注偏好、按市场和持仓/计划自动驱动。
- 计划、记实际成交、多账户持仓和可靠双向同步，属于可日用版本的定义，不应砍掉。
- 价格提醒、计划意图与实际成交事实必须分开；提醒不能直接改变持仓。
- 异常、暂停、离线、签名和推送限制要如实展示，不承诺百分之百自动。

## 没有照搬的建议

1. 评审用「账户+标的+时间+数量」描述唯一记录。主代理修正：幂等必须按稳定operation ID / transaction ID；同价同量可能是两笔合法成交，只能提示疑似重复，不能自动删一笔。
2. 评审提到将计划价量带入记成交。主代理修正：价量只能参考，不能把意图价格当成实际成交价；必须由用户输入或明确确认实际事实。
3. 评审建议字段级最后写入结合冲突。主代理修正：金融事实与账户归属不能静默最后写入覆盖；以版本前置条件、原子校验和显式冲突处理为底线。
4. 评审建议四入口「今日/计划/持仓/记录」。主代理保留用户常用的独立自选，改为「今日/自选/计划/账户」，全局记交易、账户内流水/复盘，使核心能力同样直接可达。
5. 评审分期把Watch放最后。主代理未采纳：用户已明确重视Watch镜像，必须纳入首个可日用版验收。
6. 评审示例默认锁屏显示收益百分比。主代理修正：锁屏/Watch默认仅公开行情与精简待办，不默认暴露持仓收益、数量或账户信息。
7. 自动关注使用持仓、计划、置顶的OR关系，不要求「有持仓且有活跃计划」同时成立；计划变化不能擅自解除用户当日暂停。
