# 文件夹同步与本地备份

本文说明多台 Mac 之间如何同步 FFF 的数据、冲突如何选择、以及本地备份与恢复的边界。设计背景见 [整体交易流程](../design/system-experience.md) 与 [提醒、复盘、分布与备份](../design/workflows.md)；多账号数据在各页面之间的隔离规则见 [多账号适配梳理](../audits/multi-account-audit.md)。

## 开始之前

先把各台 Mac 更新到**同一个当前 FFF 开发版本**，再在「数据与同步」设置中选择同一个同步文件夹（例如 iCloud Drive 内的文件夹）。

旧版本的冲突选择规则**不会**因为另一端更新而自动改变。两端版本不一致时，先升级再同步。

## 文件写入方式

每台 Mac 只写自己的 `Pulse-sync-<device-id>.json`，**不会直接覆盖另一台设备的文件**。因此：

- 任意一台设备都可以离线工作，恢复联网后把自己的文件放回同步目录即可。
- 云盘的上传、下载和文件协调可能有延迟。「本机已写入」不等于「另一端已经收到」。
- 判断另一端的进度，看对方是否已经生成并下载了它自己的同步文件，而不是看本机是否写完。

## 冲突选择的范围

冲突选择不是「保留哪台设备的全部数据」，而是按**依赖范围**选择：

1. **同一成交的不兼容修改**——只选择该冲突记录，其他独立成交继续合并。
2. **现金、仓位预算、预算情景、板块上限**——按**字段**选择，不替换整份账户数据。
3. **跨账户归类、计划关联或合并后超卖**——按依赖连接的**账户＋标的账本**整体选择。组内的成交、计划、份额和自选归属相互依赖，不能随意拼接；组外的独立变更继续保留。

界面会列出本次选择的范围。当前同一来源 Mac 的按钮为**已列冲突**提供一次本机/远端选择，不是逐笔独立选择。

应用选择前会保存双方快照，然后校验完整候选。如果在查看期间数据发生变化，需要重新核对，**不能强行覆盖**。

## 同步文件里有什么

同步文件是**可读的** JSON，包含账户、成交、计划和账户资金设置。请把它当作私密财务记录：不要公开上传真实数据用于报错或测试。

以下内容**不随同步文件传播**：

- 数据源凭据
- 钥匙串内容（含 MCP 令牌）
- 设备本地偏好
- 行情缓存

## 本地备份

数据与同步设置页提供本地备份，**默认开启**：

- 每次启动以及运行期间每 15 分钟检查一次，每个本地日期保存一份。
- 保留 **30 份**每日备份，以及合计 **10 份**手动／恢复前备份。
- 原子写入完整数据：自选、分组、保留历史、成交、计划和画线。
- 文件夹权限 `700`，文件权限 `600`。
- 不包含凭据及本机设置。

## 恢复

恢复流程刻意做得保守：

1. 先校验备份文件并显示预览。
2. 确认后，**必须成功保存当前状态**才能覆盖。
3. 如果预览之后数据或目标文件发生变化，恢复被拒绝。
4. 同步进行中或存在冲突时**禁止恢复**。
5. 恢复被当作一次本地编辑，会传播到已配置的同步目录。

## 验证范围

上述边界由 `PulseCore` / `PulseUI` 测试、macOS 应用构建，以及应用内 `--workflow-selftest`（临时文件和隔离偏好）覆盖，包含恢复前快照、过期预览、同步回调和错误路径。

`--main-window-demo` 的备份只使用每次启动独立的临时目录；演示模式不发送系统通知、不连接行情、也不同步。

**真实双机云盘同步属于单独的人工验收**，离线测试不宣称覆盖它。
