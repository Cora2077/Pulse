## 核心设计：单位靠目录表，不靠猜

上游把百分比、倍数、周转次数**全部塞进同一个 `value` 字符串字段**，只有指标名知道怎么读。所以配了一张目录表：认识的 id 才有标题与单位，不认识的 id 保留原始值但**不展示**。

这条规则在实测中立刻兑现：真实返回里有 `fixed_asset_invest_expansion_ratio`（固定资产扩张率），契约没给单位，界面就把它隐藏——把一个百分数当倍数印出来比少一行更糟。

单位判定的两个易错点，都有测试钉住：

| 指标 | 单位 | 依据 |
| --- | --- | --- |
| `cash_ratio`（现金比率） | **百分数** | 实测 114.736，响应语义是"现金比率 114.74%" |
| `current_ratio`（流动比率） | 倍数 | 实测 5.5895 |
| `total_assets_turnover_ratio` | 次 | 实测 0.296 |

`index_id` **不是封闭枚举**：实测 `growth` 组返回的 5 个 id 里 4 个官方文档没列（带 `calculate_` 前缀那套），文档列的 3 个反而没出现；`cash-flow` 组还比文档少 1 个。因此解析"全收 + 别名归一"，绝不因为 id 不在文档里就丢整组。

## 口径决定

1. **报告期从利润表推导，不按日历推算**。上游某期没披露时，"今天几月所以该有中报"只会换来空结果。认不出的期次标签（如 `TTM`）直接跳过，不猜。
2. **报告期本地校验**。`2026-5`、`2026-01`（两位期次）在发请求前就被拒，不拿明显写错的参数去换 `1002`。
3. **`value` 解析失败保留原始串**。数值留 nil（不补零），原始字符串仍在模型里，将来补上目录即可展示。
4. **变化列只做减法**。百分数指标的变化单位是**百分点**（`+1.09 点`），不是 `%`；不判断方向好坏——资产负债率上升既可能是扩张也可能是风险。
5. **报告期上限 4 期**。单码端点不可批取，更早的期次对"看趋势"没有增量，却按几何级数消耗预算。
6. **重复 id 保留第一条**，展示顺序按目录而非上游顺序，让同一指标在不同报告期落在同一位置。

## 请求预算

4 期 × 24h 缓存 = 每标的每日最多 **4 次**；只在财报折叠区展开后触发。与设计预估一致。
