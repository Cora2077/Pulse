# 扶摇金融数据 API：FFF 替代能力与扩展功能验证

验证日期：2026-10-20，Asia/Shanghai。范围为公开文档、用户授权 API Key 的只读请求、现有源码与定向测试。未切换日常应用的数据源配置。

## 结论

扶摇适合成为 FFF 的沪深股票快照、日线和结构化研究数据主源。当前公开接口不能完整替代腾讯的分钟行情及其他市场覆盖；推荐按能力路由，保留腾讯分时与回退。

FFF 已有 `FuyaoProvider`、凭据配置页面和 Keychain 存储。当前快照路由在已配置且启用时优先于腾讯，长桥仍排在扶摇之前。已有实现只包含股票快照、日线与搜索；ETF、指数及同花顺板块需要接入各自端点。

## 实测结果

共测试 25 个 REST 请求，其中 22 个成功，另 3 个确认能力边界。成功请求在本机这一轮耗时为 203–622 ms，中位数 259 ms；这是短轮询样本，不能解释为行情延迟或长期 SLA。

## 与腾讯交叉核对

- 同一轮请求中，茅台、平安银行、宁德时代、沪深 300 ETF、上证指数的最新价及昨收全部一致。
- 茅台重叠的 17 根日线收盘价全部一致。此区间不能验证除权日前后的复权一致性。
- 股票日线/快照文档定义扶摇成交量为股、成交额为元。腾讯股票快照的手与万元换算后基本一致；腾讯返回量存在取整差异。例如茅台扶摇为 3,413,565 股，腾讯换算后为 3,413,600 股。
- 测试发生在收盘后，不能据此确认盘中延迟、推送能力、持续可用性或稳定吞吐。

## FFF 接入前应处理的边界

1. **证券类型路由**：现有 `FuyaoProvider.swift:90` 统一走股票快照端点。ETF 搜索虽然能返回结果，但必须转至 `/api/fund/market/*`；指数和 `.TI` 板块走 `/api/a-share-index/*`。
2. **复权统一**：腾讯历史实现使用不复权，扶摇当前实现显式 `adjust=forward`（`FuyaoProvider.swift:119`）。先确定图表与价格计划的统一口径，再允许源切换；不能直接把不同口径缓存混合。
3. **缺失时间戳**：`FuyaoProvider.swift:241` 将缺失时间戳替换为 `.now`，会把无法确认时间的行情标成当前。应保留未知状态或拒绝该结果。批量时间本身是最新上游有效时间，也不等于每只证券的最后成交时间。
4. **名称解析**：快照没有中文名；扶摇当前未实现 `.referenceData`，需从标的目录/搜索补充并缓存，腾讯仍承担部分名称解析。
5. **限流与错误**：当前文档不承诺固定 QPS，也没有累计调用次数限制；需处理 HTTP 429 与 `code=4001` 并退避。不要把源码旧注释中的约 20 QPS 当作当前契约。客户端专用的 `2004` 当前会落入通用坏响应分支，新增接口时应归入权限/能力错误。
6. **字段单位按端点确认**：竞价量不能套用股票快照的股数口径。例如茅台竞价量 154.25、金额 20,376,579 元、价格 1321.01，金额/价格对应 15,425 股，量字段呈现约 100 倍差异；需核对后单独转换。龙虎榜 `change` 为小数比例，行情涨跌幅字段为百分数原值。
7. **当前与历史数据区别**：财务报告期末、实际披露日与行情就绪时间分别保留；最新龙虎榜可能仍是前一交易日。历史回测不能用当前成分股替代历史成分。

## 推荐的产品优先级

1. **行情基础**：完善股票、ETF、指数、板块类型路由与复权/时间戳语义；扶摇负责快照和日线，腾讯保留分时及回退。周/月线可另评估从统一日线聚合。
2. **盘面情绪与板块**：涨跌停、炸板、封板率、连板梯队配合同花顺行业/概念及成分股，形成可下钻的市场工作台。
3. **自选异动解释**：涨跌异动原因、热榜排名趋势与新闻时间轴放到自选卡片和复盘中，标明数据时间及来源。
4. **筹码与机构观察**：龙虎榜机构、游资及营业部信息辅助复盘，区分一日榜与三日榜，避免重复累加。
5. **基本面与本地研究**：财报、指标、估值用于研究卡片；十年全市场 Parquet + 复权事件 + DuckDB 用于本地筛选与回测准备。完整数据仓库仍需另做质量与时点验证。

主力资金、高频动向、筹码形态、成交额预测、宽基 ETF 净流入与新增概念等文档标为同花顺 AI 客户端专用；股票基础信息、个股反查所属同花顺指数等页面还有“敬请期待”。本轮只对主力资金实际验证了客户端专用响应，不应把其他未测能力写成已通过。
