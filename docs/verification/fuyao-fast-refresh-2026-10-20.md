# 扶摇行情完善与一秒刷新验收

日期：2026-10-20（Asia/Shanghai）。本文记录本次实现与验证；接口能力调查见[此前评估](fuyao-api-evaluation-2026-10-20.md)。

## 行情行为

- 股票快照使用扶摇股票端点，ETF/LOF 使用基金端点，交易所指数和同花顺板块使用指数端点。普通证券先精确解析完整 `thscode`，缓存类型与名称；元数据失败时不猜成股票。
- 支持科创 50 等未收录到语义枚举的指数，保持 `000001.SH` 上证指数与 `000001.SZ` 平安银行的身份分离。
- 股票日线改为不复权，与原腾讯图表一致；指数日线不传复权参数，窗口不超近五年。
- 基金日线接口仅提供前复权，因此继续由腾讯提供不复权日线。分钟、周、月等既有回退保留，扶摇没有的能力不伪造。
- 缺失、零、负或非有限快照时间戳拒绝入库，不补成当前时间。异常数值过滤；权限类 `2004` 不熔断整个源。
- 相同证券去重、股票/指数按最多 100 个分批；部分标的失败保留其他成功报价。

## 刷新行为

- 扶摇默认 1 秒，设置可选 1、2、5、15、30、60 秒。其他源保留自己的间隔，长桥推送优先级保持。
- 定时刷新绕过原来的 12 秒消费者报价缓存；普通一次性读取仍共享最新缓存。
- 报价按源独立运行，同源最多一个请求任务；名称与低频分时图刷新独立，不阻塞报价。
- 调度按请求开始时间计算下一次期限，不把完整轮询间隔叠加到请求耗时之后。
- 详情页中未加入自选的标的也跟随源间隔，不再固定 15 秒。
- 所有扶摇内部 HTTP 请求共用同一个 actor 节流预算，最小开始间隔 0.5 秒；遇 HTTP 429 或业务 `4001` 暂停该源并回退，不连续立即重试。
- 停止、切源、取消及写入暂停期间的旧结果不应用；取消后的响应不能污染共享缓存。
- 启动、切源或手动刷新会强制取一次，即使已经收盘。之后恢复原有休市降频，不用无变化的休市报价持续占用接口。

**一秒是目标轮询间隔，不是交易所推送或逐条价格变化保证。** ETF 端点每次只能查询一只，多只基金混合批次、网络耗时和限流可能使完整轮次超过一秒。冷启动的类型解析与名称缓存预热也可能较慢。

## 原生界面修复

主窗口原先将扶摇路由到通用数据源页面，缺少 API Key 连接入口。本次改为打开现有 `FuyaoSetupView`，与菜单栏入口一致。Key 经线上校验后保存在当前日常 App 的本机 Keychain；源代码、文档和 worker 提示均不含真实 Key。

本轮发生在收盘后：已验证接口、调度和界面，未声称完成连续交易时段的长期延迟或稳定性验收。

## 分工与交付

用户本轮将实现 worker 改回 DSH WorkBuddy `deepseek-v4.1-flash`；`AGENTS.md` 与 `scripts/dsh-worker.sh` 默认选择同步更新。Flash 提供适配与测试初稿，刷新初稿出现并发编译错误且未实现独立源调度；主 Agent 停止该 worker，收敛重写调度并修正类型路由、缓存、限流与原生入口，完成最终验证。

日常 App 路径：`/Users/cora/Applications/FFF.app`。旧 App 保存在 `/Users/cora/Applications/FFF-backups/`。应用替换不复制或删除账本与自选数据。

已在日常 App 完成实际连接，并确认重启后可以自动读取 Key。原有钥匙串条目曾出现重启后无法读取的情况；通过 App 移除本次连接项、重新保存后重启验证通过，没有改变签名要求或放宽钥匙串访问规则。

最终原生界面验收：科创 50、ETF 与股票详情均显示“同花顺扶摇”“1秒刷新”；连接页显示“已验证(API Key)”且启用开关打开。科创 50 分时图和连接页已进行实际原生截图检查。验证未修改交易、持仓或计划；安装后的可执行文件与最后构建的 SHA-256 一致。
